# v1.3.0 — Path summary toggle

**Status:** spec, awaiting owner review on the plan PR.
**Issue:** #8
**Date:** 2026-10-08
**Plan:** `docs/designs/v1.3.0-path-summary-plan.md`

## What this is

A `summary` button in the nav row, placed directly after `focus` and styled
with an inverted colour scheme. Selecting it opens a compact block at the top
of the Schedule overview, above the `Queue fin:` line. The block answers the
question the panel cannot answer today: *what does this whole path get me?*

The summary is transient. It closes when the player uses any other tab or
control, and it is never written to storage.

## Why it exists

The Schedule view answers *when*, through the finish date and the booster
scenarios. It never answers *what*. A queue's gains are spread across one
indented bonus line per row, and nothing adds them up. A player comparing a
40-course plan with a 60-course plan has to scroll both queues and total them
by hand.

## Decisions

These were open questions in the request. Each is settled here so the plan
has nothing left to guess. The owner can overturn any of them on the PR.

| # | Question | Decision | Why |
| --- | --- | --- | --- |
| D1 | Where does it render? | Inside `.tes-schedule-overview`, as its first child, above `.tes-finish`. | The request names the Queue fin box, and the overview is the box that holds it. Rendering inside the overview keeps one outlined surface rather than stacking two. |
| D2 | What does the button do off the Schedule view? | It switches to Schedule **and** opens the summary in one click. | The Queue fin box exists only on Schedule. A button that does nothing on three of four views would read as broken. |
| D3 | What closes it? | Every handler except the summary's own toggle. This is enforced by **wrapping** the handler set, not by editing each handler. | The request says "whenever another tab or option is selected". `resetArmed` is cleared in about 20 handlers by hand, which is how a future handler forgets it. A wrapper makes closing the default for any handler added later. |
| D4 | Does a second click close it? | Yes. The button is a toggle, with `aria-pressed` reflecting the state. | That is what "toggle button" means. |
| D5 | Is it persisted? | No. It lives in `init()`'s closure beside `resetArmed`. A fresh `init()` (route change, remount) starts closed. | The same rule `view` and `resetArmed` already follow: the panel you last looked at is not a preference. |
| D6 | What when there is no honest finish date? | The button stays visible but is **disabled**, with a `title` explaining why. Applies to an empty queue, unmet prerequisites, and the error and loading models. | `buildPanelModel` withholds `finishLabel` and `totalLabel` whenever the queue cannot be followed. A summary of an unfollowable path would print totals the panel elsewhere refuses to stand behind. Disabled rather than absent, so the nav row does not reflow as the queue changes. |
| D7 | Which colour scheme is "inverted"? | Closed: light fill (`--tm-text`) with dark text. Open (pressed): green fill (`--tm-good-text`) with the same dark text. | Every other button is light text on a dark fill. This is the only control in the panel that is the reverse, which is the point. |
| D8 | How are improvements totalled? | One figure per `(category, selection)`, never summed across selections or units. | The same rule focus mode is built on (`docs/designs/v0.3.0-focus-mode.md`). Adding a percent bonus to a flat stat invents an exchange rate. |

## What the summary shows

Order is fixed. Each line is omitted when it has nothing to say, never shown
empty.

1. **Headline.** `23 courses · 2 degrees · 87 days 4 hrs`. The course count
   is the ordered queue's length. Degrees are queued tier-3 courses. Time is
   `model.totalLabel`, the same string as `Total queued time`, reused rather
   than reformatted.
2. **Dates.** `Finishes 2027-01-04 · 13:00 TCT`, reusing `model.finishLabel`.
   When `model.consumables` is present, the line adds
   `· Books floor 2026-12-01 · 09:00 TCT`, reusing `consumables.floorFinishLabel`.
3. **Working stats.** `+1,240 intelligence · +600 endurance · +300 manual labor`,
   summed through `workingStatsFor` over the queued courses. A stat with a zero
   total is omitted.
4. **Bonuses.** One line per taxonomy category that has a non-zero
   contribution, in `FOCUS_CATEGORIES` order excluding Working Stats:
   - percent and flat selections render as `selection +N%` or `selection +N`,
     largest first, with at most **four** per line, then `+N more`
   - `count` selections (unlocks, and anything in `FOCUS_UNSTATABLE`) collapse
     to one `N unlocks` figure for the category, because a count of abilities
     has no magnitude to rank
5. **Health note,** only when `focusHealth` reports stale or unmapped rows:
   `Some bonuses could not be matched to Torn's current course text and are not counted.`
   This says what the totals leave out, the same honesty `focusRemainingLabel`
   keeps.

All text is set through `textContent`. Selection and category names come from
the taxonomy constants, but the rule is unconditional anyway.

## Architecture

### Engine: `pathGains(queue, courses)`

A new pure function between `ENGINE START` and `ENGINE END`, beside
`focusTotals`. `tests/purity.test.js` already enforces that section.

Input: the ordered queue (`number[]`) and the course `Map`.
Output:

```js
{
  courseCount: number,
  degreeCount: number,              // queued courses with tier === 3
  workingStats: [{ stat, amount }], // WORKING_STATS order, zero amounts dropped
  categories: [{
    category,
    gains: [{ selection, unit: 'percent' | 'flat', amount }], // amount desc, then selection asc
    unlockCount: number,                                      // distinct count-unit selections
  }],                                                         // FOCUS_CATEGORIES order, empty dropped
}
```

Rules:

- **Dedupe by course id before summing.** A duplicated queue id counts once.
  `focusTotals` does the same for the same reason: `loadPlan` dedupes today,
  but the engine does not lean on that.
- **Read the registry, not the raw taxonomy.** Rows come from
  `focusRegistry(courses).entries`, so a stale row (outcome text Torn changed)
  contributes nothing rather than a number the payload no longer supports.
- **One magnitude per `(category, selection, courseId)`.** This is the same
  dedupe `focusTotals` applies, so a split outcome listed twice under one
  selection does not double.
- **`FOCUS_UNSTATABLE` forces `count`.** Rig Overclocking Limit's "up to 30%"
  and "up to 50%" are successive caps, not additive. Summing them gives the
  80% ceiling `tests/focus.test.js` already guards against.
- **Unknown or absent input degrades to zeros, never throws.** A non-array
  queue, a non-`Map` catalogue, or an id missing from the catalogue all give
  empty output, matching `focusTotals`' contract.

### Model: `buildPanelModel` gains `pathSummary` and `summaryOpen`

- `pathSummary` is `pathGains(queue, courses)` plus the formatted strings the
  view needs. It is gated on **exactly** `queue.length > 0 && problems.length
  === 0`, the gate `finishLabel`, `totalLabel` and `consumables` already share,
  and is `null` otherwise and on both failure models. One gate, so the button's
  disabled state and the finish date cannot disagree.
- `summaryOpen` is `state.summaryOpen === true && pathSummary !== null`. A
  summary cannot be open with nothing to show, even if a queue edit removed the
  data between draws.
- `errorModel()` and `loadingModel()` carry `pathSummary: null` and
  `summaryOpen: false`, kept in step by hand the way that model's comment
  already describes.

### Nav: one button that is not a view target

`renderPanel`'s left group appends the summary button after the `focus` loop
entry, or after `degrees` when focus is hidden. It is not a view target, so it
does not go through `onViewChange`. It is a plain button with:

- class `tes-path-summary-toggle`, plus `tes-path-summary-open` when open
- label `summary`
- `aria-pressed` set to `"true"` or `"false"`
- `disabled` and a `title` when `model.pathSummary` is null
- a click listener that checks `btn.disabled` itself (the established guard
  for fake-document harnesses), then calls `handlers.onSummaryToggle`

The class name avoids `.tes-summary`, which already exists and styles the
`Total queued time` block.

### Handler: `onSummaryToggle` and the closing wrapper

In `init()`:

- `let summaryOpen = false;` beside `resetArmed`, with the same comment shape.
- `onSummaryToggle` clears `resetArmed` and `presetError` like every other
  handler. When the view is not `schedule`, it sets `view = 'schedule'` and
  `summaryOpen = true`. Otherwise it flips `summaryOpen`. Then it redraws.
- The handler object passed to `renderPanel` is built as today, then passed
  through `closesSummary(handlers, except)`. That small runtime helper returns
  a new object whose every function-valued property first sets
  `summaryOpen = false` and then calls the original, except the keys in
  `except` (`['onSummaryToggle']`). It is a closure inside `init()`, because
  it writes `init()`'s own variable.

`noopHandlers` gains `onSummaryToggle` as a no-op, the same rule that already
covers `onAddAll` and `onImportPlan`.

### Style

Two rules in `panelStyleText()` and one new token.

- **New token `--tes-ink-on-light: #1f1f1f`** in the token block. The style
  test forbids using a background token as text. It is right to, because a
  token named for a surface should not be repurposed as ink. An inverted
  control needs a dark *ink*, so it gets one, named for what it does.
- `.tes-path-summary-toggle`: `background: var(--tm-text); color:
  var(--tes-ink-on-light); border-color: var(--tm-text)`.
- `.tes-path-summary-toggle.tes-path-summary-open`: `background:
  var(--tm-good-text); border-color: var(--tm-good-text)`, same ink.
- `.tes-path-summary-toggle:disabled`: back to the ordinary button fill (`--tm-hover`) with `--tm-muted` text and `cursor: not-allowed`. The panel has no generic disabled-button rule to inherit, so this one is explicit. A disabled inverted
  button must not look like a live one.
- `.tes-path-summary` (the block): divided from the finish line by a bottom
  border in `--tm-border-2`, using `--tes-gap` spacing. No new surface or card,
  because the overview outline is already the surface.

Contrast is asserted, not assumed. The new style test computes `ratio()` for
`#1f1f1f` on `#ffffff` (16.5) and on `#7ee081` (10.1). Both clear AA.

Mobile: the nav is already a two-column grid under the PDA breakpoint. Six
buttons (with focus) fill three rows and five leave one cell empty, which the
grid already handles. No breakpoint change.

## What does not change

- No arithmetic. `schedule`, `planConsumables` and `orderQueue` are untouched,
  and the summary only reads labels the model already builds.
- No storage key, no share-string field, no debug-report field.
  `tests/storage.test.js` gains an assertion that neither stored blob ever
  carries `summary`.
- Security surface: no `@match`, `@grant` or `@connect` change.
