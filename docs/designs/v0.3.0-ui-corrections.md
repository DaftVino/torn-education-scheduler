## Owner decisions

**1. macOS users lose the bachelor marker entirely.** Item 8 removes the
`[bachelor]` prefix and replaces it with `color: #7ee081` on the `<option>`.
That works on Chrome and Firefox under Windows and Linux. On macOS the OS draws
the menu and commonly ignores the colour, so those players see **no marker at
all** — not a degraded one. `docs/code-map.md` records the prefix's existence
with the reason "an `<option>` being unstylable in any portable way", so this
knowingly trades that constraint away. The alternatives are to keep the prefix
as a macOS fallback (which reintroduces what the item asked to remove, for some
users only) or to replace the `<select>` with a custom listbox (a much larger
change, and one that owes keyboard and screen-reader behaviour the native
element gives for free). **Confirm the trade before this is planned.**

**2. Abbreviations are display-only.** Item 3's `crs`/`hrs`/`fin` never reach
the share string or the debug report, both of which are copied out of the panel
and sent to other people. That means a second, panel-only duration formatter
beside `formatDuration`. Confirm that is wanted rather than one formatter used
everywhere.

## What this is

Eight presentation and navigation corrections for the education planner. They do not change scheduling logic, stored data, permissions, or network access. New DOM lookups must be null-guarded and render a visible `.tes-error` message when required structure is unavailable.

## Conflicts resolved up front

### A. Right-aligned settings and reset/default

The navigation order is:

1. Planner destinations: `schedule` and/or `degrees`.
2. Flexible gap.
3. `⚙ settings`.
4. The existing `reset` or `defaults` control.

Apply `margin-left: auto` only to the settings button, the first child in the right-hand group. Reset/default follows normally and remains at the row’s extreme right. A second auto margin is prohibited.

On schedule, show `degrees`; on degrees, show `schedule`; on settings, show both as exit destinations. Settings is always present while the navigation body is visible. On the settings view it is marked `aria-current="page"` and is a no-op or disabled, never a toggle.

### B. Bachelor highlighting in native selectors

Recommendation: retain the native `<select>`, remove the `[bachelor] ` prefix, give bachelor `<option>` elements a class, and apply `color: #7ee081`.

Chrome and Firefox on Windows and Linux normally show the green. Native menus on macOS may ignore the color, so those users may see an ordinary unmarked option. The textual prefix does not survive as a fallback because that would contradict the requested removal. A fully portable green treatment would require a separate accessible custom-listbox project; this change does not claim portable styling.

### C. Display abbreviations versus copied data

`crs`, `hrs`, and `fin` are panel-display abbreviations only.

Keep `formatDuration()` as the canonical long formatter for share strings, debug reports, and other copied output. Add a panel-only duration formatter that emits days unchanged and `hrs` for the hour component. Course-count and `fin` substitutions happen in renderers, not in stored data or serialization.

The picker-label builder, schedule renderer, queue-row renderer, and degree-grid renderer may emit the abbreviations. `formatDuration()`, the share-string serializer, and the debug-report builder may not.

## 1. Permanent settings navigation

Replace the current “skip the active view” loop with explicit planner-navigation and utility-navigation construction.

- Schedule view: `degrees` on the left.
- Degrees view: `schedule` on the left.
- Settings view: `schedule`, then `degrees`, on the left.
- Every expanded view: `⚙ settings` in the right-hand group.
- Reset/default follows settings, as resolved above.

The settings button still calls `handlers.onViewChange('settings')` outside the settings view. The active settings button must not trigger redundant rendering. Collapsing the panel may continue to hide the entire body, including navigation.

## 2. ISO timestamps

Change `formatTimestamp(seconds)` to produce UTC ISO 8601 timestamps in this exact form:

`2026-08-04T21:00:00Z`

Keep UTC so the value can be compared directly with Torn’s clock. Show seconds; omit milliseconds. All scheduler-rendered timestamps, including queue completion and degree completion estimates, use this formatter.

Unknown or intentionally withheld timestamps remain absent. Do not manufacture an ISO value from invalid input.

## 3. Compact panel wording

Add a display-only duration formatter with these outputs:

- `0 hrs`
- `1 hrs`
- `8 hrs`
- `1 day 3 hrs`
- `2 days`

Use `crs` for rendered course counts regardless of count. Replace visible `finishes` labels with `fin`, including queue rows and the schedule heading (`Queue fin:`). Keep `.tes-finish` as the heading’s class and color source.

Do not change canonical duration text used by copied share strings or debug reports.

## 4. Course bonuses in queue rows

Change each selected-course row to a two-line grid:

- First line: existing course prefix, name, compact duration, and `fin` timestamp when valid.
- Second line: an indented, smaller bonus description.
- Right column: `remove`, spanning both rows with `grid-row: 1 / span 2`.

Use a queue-specific modifier such as `.tes-queue-row`; do not change every `.tes-row` into a grid.

Build the bonus line from `FOCUS_TAXONOMY[courseId]` and the parsed result of `workingStatsFor(course)`. Show only authored or parsed facts; do not infer a bonus from a course name.

For the 31 courses without `learningOutcomes`:

- If working-stat gains parse successfully, show those gains followed by `other bonus not listed by Torn`.
- If no reliable gain exists, show `Bonus: not listed by Torn`.

This UI is not blocked on the focus-mode interface shipping first, but it has a code-order dependency: `FOCUS_TAXONOMY` and `workingStatsFor()` must be available before this renderer lands. Do not duplicate the taxonomy.

Set every dynamic fragment with `textContent`, including course names and bonus text.

## 5. Real header button

Split `.tes-header` into:

- `.tes-header-title`, containing only `VIEW_TITLES[view]` or the schedule fallback.
- `.tes-header-toggle`, a real `<button>` containing `hide` or `show`.

Make the header a flex row and apply `margin-left: auto` to the toggle. Remove the click handler and pointer cursor from the header container; attach `handlers.onToggle` only to the button. The button inherits the existing panel-button styling.

Existing tests that assert the aggregate `.tes-header.textContent` must instead assert the title and button independently.

## 6. “All remaining courses” banner

In the grid-model builder containing `boxFor('all', ...)`, keep the all-remaining calculation but expose the result separately from the degree-card collection. Use the exact visible title `all remaining courses`.

The degrees renderer places this item before the degree grid as a full-width `.tes-all-banner`, not as `.tes-cell`. Its detail uses compact panel wording and ISO timestamps.

Degree boxes remain cards. Existing ambiguity handling remains unchanged: a degree card has no name when ownership cannot be determined reliably. `sumsDiffer` continues comparing the summed degree counts with the all-remaining count.

## 7. Structured schedule summary

Replace the single newline-joined text node with real child elements:

1. `.tes-summary-inputs`: perk reduction.
2. `.tes-summary-result`: total queued time, empty-queue guidance, or the unfollowable-plan warning.
3. `.tes-summary-diagnostics`: stale entries and prerequisite problems, when present.

Put a visible top border, padding, and margin on `.tes-summary-result`. This separator distinguishes the scheduling assumption from the resulting queue duration.

Each message is its own element populated with `textContent`; `.tes-summary` no longer depends on `white-space: pre-line`. Diagnostics remain below the queue result without another required separator.

## 8. Bachelor-course highlighting

Change the picker-label builder from:

`[bachelor] PREFIX Name (duration)`

to:

`PREFIX Name (duration)`

Mark bachelor options structurally, for example with `.tes-option-bachelor`, and apply `color: #7ee081`, matching `.tes-finish`. Non-bachelor options retain the normal selector color.

This styling is best-effort for native selectors. On macOS, the operating-system menu may ignore it; no `[bachelor]` prefix or replacement text marker is retained.

## Behaviour

| Condition | Behaviour |
|---|---|
| Schedule view | Show `degrees`; show right-aligned settings followed by reset. |
| Degrees view | Show `schedule`; show right-aligned settings followed by reset. |
| Settings view | Show `schedule`, `degrees`, active settings, then defaults. |
| Panel collapsed | Show the header and real `show` button; body navigation may remain hidden. |
| Valid timestamp | Render `YYYY-MM-DDTHH:mm:ssZ` in UTC. |
| Invalid or withheld timestamp | Render no date or finish label. |
| Zero-hour duration | Display `0 hrs` in the panel. |
| Share/debug duration | Retain canonical unabbreviated wording. |
| Course has taxonomy and working-stat data | Show both reliable bonus components. |
| Course lacks `learningOutcomes` but has parsed working stats | Show the stats and `other bonus not listed by Torn`. |
| Course has no reliable bonus data | Show `Bonus: not listed by Torn`. |
| Queue is unfollowable | Show the warning and prerequisites; withhold finish timestamps. |
| Queue is empty | Show the existing empty-queue guidance in the result section. |
| All courses are complete | Banner shows `Already complete`. |
| Degree ownership is ambiguous | Keep the degree name blank. |
| Bachelor option on supported native menu | Show the option in `#7ee081` without a prefix. |
| Bachelor option on macOS menu that ignores option color | Show an ordinary unmarked option; do not restore the prefix. |
| Required DOM structure is missing | Stop that render/action safely and show a visible `.tes-error`; never dereference null. |

## What this does not change

- Course ordering, prerequisite validation, duration calculations, reduction calculations, or completion estimates.
- The rule that unreliable names, dates, and costs are withheld rather than guessed.
- Share-string and debug-report schemas, except that timestamps already routed through `formatTimestamp()` become ISO.
- Focus-mode filtering or focus-mode controls.
- Storage keys, migration behavior, Torn API access, metadata grants, or connection permissions.
- Dependencies or build tooling.
