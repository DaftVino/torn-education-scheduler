# v0.3.0 § H6 — Colour token system

**Status:** spec, ready to plan. **Sequenced last — see "This goes last".**
**Date:** 2026-08-04
**Source:** `X:\Projects\Torn Bookie Live Scores`, default ("Default Dark")
scheme, `Torn_Bookie_Live_Scores.js:8244-8277`.

## What this is

Replace every hardcoded colour in the panel's stylesheet with a CSS custom
property, using the `--tm-*` token names and default-scheme values from Torn
Bookie Live Scores. One theme only. **No theme switcher**, no stored theme
preference, no settings control — this is a refactor of how colour is
expressed, not a feature.

`CLAUDE.md` already says the panel is "modelled on Torn Bookie Live Scores".
Today that resemblance is by eye and by accident. Tokens make it structural, so
the two panels drift together instead of apart, and so a future theme is a
change of values rather than a rewrite of rules.

## This goes last

**Implement only after § H3 (focus mode), § H4 (reset controls) and § H5 (UI
corrections) have landed.**

Each of those adds new styled elements: a focus view with per-selection rows,
an armed-state reset button in a warning colour, a header toggle button, an
all-remaining banner, a structured schedule summary with a separator border,
and a green bachelor option. Tokenising first means tokenising again for every
one of them, and worse, it means three specs choosing hardcoded colours that a
fourth then has to hunt down. Going last, this pass sees the finished surface
once.

**§ H5 item 8 is the specific coupling.** It introduces `#7ee081` as an
`<option>` colour by naming the literal. When this spec runs, that literal
becomes a token — so H5 must not be written in a way that makes the hex hard to
find. One occurrence, in the stylesheet, is fine.

## The source has two different "defaults"

Bookie declares the default scheme twice, with values that disagree:

| Token | Panel root (`:8245`) | `.tm-theme-default` (`:10077`) |
| --- | --- | --- |
| `--tm-text` | `#ffffff` | `#e0e0e0` |
| `--tm-accent` | `#cc0000` (red) | `#6ea3d0` (blue) |
| `--tm-good` | `#2a6b3a` | `#5dba6d` |
| `--tm-bad` | `#a33` | `#e06060` |
| `--tm-border` | `#3a3a3a` | `#333` |
| `--tm-bg-4` | `#191919` | `#2f2f2f` |
| `--tm-hover` | `#292929` | `#333` |

**The panel root is canonical here.** It styles Bookie's main floating panel,
which is the thing this project's panel is modelled on; `.tm-bookie-details` is
a nested detail component with its own local palette. Adopting the details
palette would copy a sub-component's overrides and call them the house style.

This disagreement is a finding about the source, not about this project. It is
recorded here so the next person does not "fix" our tokens to match the other
block. **Worth reporting upstream to the Bookie repo** — two blocks both
claiming to be the default is a bug there whichever one is right.

## The green does not survive the move, and neither do the red or the accent

Bookie uses `--tm-good`, `--tm-bad` and `--tm-accent` predominantly as fills,
borders and badges. This panel uses green and red as **text** — the finish date
line and the error line are coloured type on a dark background. Measured
against `--tm-bg` (`#1f1f1f`):

| Token | Value | As text on `--tm-bg` | WCAG AA (4.5:1) |
| --- | --- | --- | --- |
| `--tm-good` | `#2a6b3a` | **2.56:1** | ✗ fail |
| `--tm-bad` | `#a33` | **2.54:1** | ✗ fail |
| `--tm-accent` | `#cc0000` | **2.80:1** | ✗ fail |
| `--tm-warn` | `#ffcc00` | 10.90:1 | ✓ |
| `--tm-text` | `#ffffff` | 16.48:1 | ✓ |
| `--tm-muted` | `#b8b8b8` | 8.31:1 | ✓ |
| `--tm-meta` | `#cfcfcf` | 10.58:1 | ✓ |

What the panel uses today:

| Current | Role | On `#1c1c1c` |
| --- | --- | --- |
| `#7ee081` | `.tes-finish` — the number this tool exists to produce | **10.44:1** |
| `#e6e6e6` | body text | 13.65:1 |
| `#ff8080` | `.tes-save-error`, `.tes-error` | 7.02:1 |

**Naively adopting `--tm-good` for the finish date takes it from 10.44:1 to
2.56:1** — a fourfold contrast regression on the single most important line in
the panel, and a failure of the one accessibility bar that has a number
attached to it.

So the token set gains three text-safe siblings, and the rule is explicit:

```css
--tm-good: #2a6b3a;          /* fills, borders, badges — Bookie's value, unchanged */
--tm-good-text: #7ee081;     /* coloured type on --tm-bg — this panel's existing green */
--tm-bad: #a33;              /* fills, borders */
--tm-bad-text: #ff8080;      /* coloured type — this panel's existing red */
--tm-accent-text: #6ea3d0;   /* if accent is ever needed as type */
```

`--tm-good-text` and `--tm-bad-text` keep the panel's current values precisely
because those values already pass. **The visible result of this entire spec
should be no visible change**, which is the strongest evidence a token refactor
did what it claimed.

The naming carries the rule: a token ending `-text` is for type, one without is
not. A reviewer seeing `color: var(--tm-good)` knows it is wrong without
measuring anything.

## Token set

Adopted from the panel root block, verbatim unless noted:

```css
#tes-panel {
  --tm-bg: #1f1f1f;
  --tm-bg-2: #242424;
  --tm-bg-3: #111111;
  --tm-bg-4: #191919;
  --tm-hover: #292929;
  --tm-border: #3a3a3a;
  --tm-border-2: #555555;
  --tm-text: #ffffff;
  --tm-muted: #b8b8b8;
  --tm-meta: #cfcfcf;
  --tm-accent: #cc0000;
  --tm-warn: #ffcc00;
  --tm-good: #2a6b3a;
  --tm-bad: #a33;
  --tm-good-text: #7ee081;    /* added — see above */
  --tm-bad-text: #ff8080;     /* added */
  --tm-accent-text: #6ea3d0;  /* added */
  --tm-focus: var(--tm-accent);
  --tm-font: Arial, Helvetica, sans-serif;
}
```

**Not adopted:** `--tm-card-*` (no card surface here), `--tm-source-*` (score
providers, meaningless in this project), `--tm-success/-info/-warning/-danger`
and their `-bg` pairs, and `--tm-game-*`. Carrying tokens nothing references
makes the set look like a design system and behave like dead code.

**`color-mix()` is not adopted.** Bookie derives its `-bg` variants with
`color-mix(in srgb, …)`. Nothing here needs a translucent fill today, and
adding an unused dependency on a newer CSS function for the pleasure of
symmetry is the kind of thing this repo does not do.

## Mapping

Every hardcoded colour currently in the stylesheet:

| Current | Becomes | Note |
| --- | --- | --- |
| `#1c1c1c` panel background | `var(--tm-bg)` | `#1f1f1f`, a hair lighter |
| `#4a4a4a` panel and button borders | `var(--tm-border-2)` | `#555555` |
| `#e6e6e6` body and button text | `var(--tm-text)` | `#ffffff` |
| `#2e2e2e` button background | `var(--tm-hover)` | `#292929` |
| `#7ee081` `.tes-finish` | `var(--tm-good-text)` | unchanged value |
| `#7ee081` button `:hover` border | `var(--tm-good-text)` | unchanged value |
| `#ff8080` `.tes-save-error`, `.tes-error` | `var(--tm-bad-text)` | unchanged value |
| Arial stack, wherever inherited | `var(--tm-font)` | |

Four background and border values shift by a few points of luminance. That is
the whole visible delta, and it is the point: the panel adopts Bookie's greys
exactly rather than approximately.

Elements added by H3/H4/H5 are tokenised in the same pass, against the same
table. Anything they introduced that has no token gets one here rather than
staying a literal.

## Rules this establishes

1. **No hex literal outside the token block.** One place declares colour.
2. **`-text` tokens for type, plain tokens for fills.** Never `color:
   var(--tm-good)`.
3. **Any new coloured type meets 4.5:1 against `--tm-bg`**, measured, not
   judged by eye.
4. **Token values come from Bookie's panel root**, not from
   `.tm-theme-default`, and not invented here. The three `-text` additions are
   the only local values, and each exists because a Bookie token failed a
   contrast measurement.

## Behaviour

| Condition | Behaviour |
| --- | --- |
| Panel renders normally | Visually near-identical to today; only greys shift |
| A browser without CSS custom property support | Not supported — custom properties are universal in any browser Tampermonkey runs on. No fallback declarations |
| Torn's own page CSS declares `--tm-*` | Scoped to `#tes-panel`, so the panel's declaration wins for its own subtree |
| A future theme is wanted | Change values on the `#tes-panel` block. Out of scope here |

## Testing

Styles are a string in this codebase, so they are testable as one.

1. Assert the stylesheet contains **no hex colour literal outside** the token
   block — a regex over the emitted CSS string. This is the test that keeps
   rule 1 true after this session ends.
2. Assert every `--tm-*` token declared is referenced at least once, and every
   `var(--tm-*)` referenced is declared. Both directions: an undeclared token
   renders as nothing, and an unreferenced one is dead weight.
3. Assert `.tes-finish` resolves to `--tm-good-text`, not `--tm-good`.
4. Assert `.tes-save-error` and `.tes-error` resolve to `--tm-bad-text`.
5. A contrast test with the ratio computed in the test itself, asserting every
   `-text` token clears 4.5:1 against `--tm-bg`. Hardcoding the expected ratios
   would let a token change silently break the thing the test exists to
   protect.
6. Assert no `color-mix(` appears in the stylesheet.
7. Assert the token block is scoped to `#tes-panel` and nothing is declared on
   `:root` — the panel must not leak variables into Torn's page.

## Open questions

- **Does the owner want `--tm-bg` (`#1f1f1f`) or to keep `#1c1c1c`?** Adopting
  Bookie's value is the point of the exercise, but it is a real, if small,
  visible change to a panel that has shipped. This spec adopts it.
- **Report the duplicate default upstream?** The two disagreeing blocks in
  Bookie are a defect there. Worth an issue on that repo.

## What this does not change

- Any behaviour, any arithmetic, any stored data.
- The security surface: no new grant, no network, no storage key.
- Zero dependencies, no build step.
- Layout, spacing, typography scale, or any element's structure — colour only.
